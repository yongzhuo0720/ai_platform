## 二、每批次标准执行流程（任务书第五节）

每个问题/每组强相关问题，严格按以下 8 步：

1. **明确问题**：引用问题清单编号，说明要解决什么。
2. **定位源码**：给出文件:行号，读实际代码。
3. **分析原因与影响范围**：不臆测，基于代码事实。
4. **提出修改方案**：最小必要修改，说明备选方案与取舍。
5. **实施修改**：只改必要代码，不做顺手重构。
6. **运行对应测试**：先跑针对性单测，再跑全量。
7. **检查回归**：对比修改前后测试结果；区分原有失败与本次引入失败。
8. **汇报**：修改文件、修改内容、原因、修复问题、测试真实结果、未解决问题、是否建议下一批。

**禁止**：删除测试让它通过、改测试预期掩盖问题、伪造未执行的测试结果、擅自破坏性操作（见任务书第六节）。

## 三、第一批：安全与稳定性

### 3.1 P2-1 异常回显原始消息
- **方案**：`GlobalExceptionHandler.handleBadRequest` 对 `IllegalArgumentException`/`IllegalStateException` 返回固定文案；完整消息写日志。`KbRagHolder:355-356` 改通用提示。
- **修改文件**：`GlobalExceptionHandler.java`、`KbRagHolder.java`、新增 1 个单测。
- **验证**：新增 sentinel 单测（响应不含 sentinel、日志含）；`mvn -o test` 757+ 项全过。
- **风险**：低。可能有个别前端依赖错误文案做判断——需 grep 前端是否匹配具体错误消息。

### 3.2 P2-2 actuator 暴露
- **方案**：优先**部署层**解决——nginx 配置限制 `/actuator/**` 为内网；不改应用代码（避免引入 Spring Security 依赖，符合"不换技术栈"原则）。备选：prometheus 绑独立管理端口。
- **修改文件**：`docs/nginx-multinode.conf.example`、README 部署说明。
- **验证**：从公网 IP curl `/actuator/prometheus` 被拒；env/heapdump/threaddump 仍 404。
- **风险**：低；需你确认部署网络边界。

### 3.3 P2-3 SSO state 绑定
- **方案**：state 改随机 nonce + 服务端 `nonce↔uid` 映射（Redis，TTL 10min）+ callback 原子消费；缓存 token 前校验 sub 与 state uid 一致。
- **修改文件**：`SsoTokenBeanController.java`、`SsoTokenBeanHolder.java`、新增单测。
- **验证**：单测：state 重放被拒、过期被拒、sub 不匹配被拒；SSO 相关 + 全量测试。
- **风险**：中——SSO 是认证链路，需确保未启用 SSO 的环境不受影响（当前 `sso.enabled=false`）。

### 3.4 P1-1 doProxy 拆分（本批末位）
- **方案**：按"准入 → 上游执行 → 响应中继 → 收尾结算"拆私有方法，用上下文对象承载状态；**纯结构重排，不改任何行为**。
- **修改文件**：仅 `AiGatewayService.java`（+ 可能新增内部上下文类）。
- **验证**：`mvn -o test` 全部（重点 `AiGateway*Test` 计费/熔断/断流）、`check:streaming` 14 项、E2E 23 项；对比同一 mock 上游 usage/成本数值。
- **风险**：**高**——核心路径 397 行，虽是结构重排但仍可能引入回归。建议放在本批最后，**若前 3 项完成后你希望暂停，可单独决策是否继续此项**。
