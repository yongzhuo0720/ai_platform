# 智汇平台 · 知识库文档

## 项目简介

智汇平台是一个面向企业内部的 AI 能力门户。它把智能对话、知识库问答、能力广场、模型仓库、数据集、场景应用等多个 AI 相关模块整合到同一个平台里，并按角色和部门做细粒度的可见性控制。

AI 的向量化、检索与编排由 Dify 承担，本平台负责用户体系、权限模型、多模块聚合与前端交互体验。

一句话定位：本平台不"思考"，只负责「谁能用、看得到什么」；真正的 AI 能力在 Dify 那一侧。

## 技术栈

前端：Vue 3、TypeScript、Vite 5、Element Plus、Pinia、vue-router（hash 模式）。

后端：Spring Boot 2.6.8（Java 8）、MyBatis-Plus、Druid、Sa-Token，基于 HNSP 快速开发框架。

存储：PostgreSQL（数据库 ai，schema public）和 Redis。

AI 能力：Dify（对话、工作流、知识库）与 Qwen 模型服务。

## AI 调用治理网关

本平台最关键的架构决策是：**AI 请求统一收口到业务后端网关**。

网关通道（默认）：浏览器请求 `/ai/api/aiGateway/{chat|knowledgeChat|file|agent}/...`，由 Spring Boot 携带服务端凭据转发上游。Dify 通道使用服务端 Dify Key；智能体通道使用 `AGENT_*` 环境变量或 `assistantbean` 中的 Token / Agent ID，并按助手可见性校验调用者。网关负责 SSE 逐块透传、按用户每分钟限流、每日 Token 配额（仅 Dify）、调用审计（模块、状态、tokens、耗时、模型、会话 ID、客户端 IP），后台「AI 调用治理」提供用量看板、日志与配额管理。

平台通道：URL 前缀为 `/ai/api` 的其他请求经过 Spring Boot，带 Sa-Token 鉴权，可以写 PostgreSQL、记录操作日志。

直连通道（兼容）：设置 `VITE_AI_GATEWAY=0` 后，浏览器可经 Nginx/Vite 直连 Dify 或智能体服务，请求头带 Bearer 凭据。延迟低但浏览器持有密钥，且没有限流/配额/审计。

这个设计的取舍是：凭据不下发浏览器、调用可计量可治理；代价是多一跳网关延迟和 SSE 代理复杂度。早期直连方案已降级为排障用的兼容开关。

智能体通道额外做了两点：上游地址只取服务端配置，忽略助手记录里的 `apiUrl`（防 SSRF）；浏览器传来的 `Authorization` / `X-Agent-Id` 会被网关覆盖，无法冒充其他助手。

## 数据归属：kbId 弱引用

文档原文、分块和向量全部存放在 Dify 中，本平台数据库里没有任何文档内容。

本平台的 PostgreSQL 里有一张 knowledgebasebean 表，只存权限元数据：kbId（指向 Dify 的 dataset.id）、ownerUid（所有者）、permissionType（可见性）、unitsnos 和 roleiids（部门与角色黑名单）。

两边通过 kbId 关联，没有外键约束。因此如果有人在 Dify 后台直接删除知识库，本平台会留下孤儿权限记录，这是已知的取舍。

## 权限模型

知识库支持三种可见性（permissionType）：

public：所有人可见。

only_me：仅所有者可见。

partial_invisible：按部门和角色黑名单排除，落在 unitsnos（部门）或 roleiids（角色）黑名单中的用户不可见。

权限配置解析失败时按不可见处理（fail-closed 原则），避免"配错了反而全放开"。

未知权限类型一律拒绝，同样是为了避免配置错误导致资源意外公开。

## 安全设计

越权防护：能力广场、模型库等平台级目录的写操作限超管；用户归属资源逐条校验所有者。

文件下载：路径必须落在已登记的数据集根目录内，做规范化后前缀比对，越界返回 403。

密钥治理：源码中历史遗留的硬编码密钥已全部移除，改为配置下发，本地开发用环境变量覆盖。Dify Key 与智能体 Token 都不下发浏览器；智能体通道会覆盖客户端传入的认证头，上游地址固定为服务端配置。

XSS 防护：助手回答中的原始 HTML 做转义，图片 URL 做协议校验。

## 常见问题

问：这个项目的 AI 是自己研发的吗？

答：不是自研的。RAG 的向量化、索引和检索由 Dify 提供，本平台做的是平台层：多知识库的权限体系、本系统与 Dify 数据集的映射管理、前端 SSE 流式接入，以及上传到索引到检索到回答整条链路的串联。

问：API Key 怎么管理的？

答：Dify Key 和智能体 Token 都只存服务端（数据库或后端环境变量），浏览器不持有。早期是浏览器直连带 Key 的方案，延迟低但无法限流和审计；现已改为后端网关，网关按用户限流、按每日 Token 配额拦截，并记录完整审计。智能体通道同样经网关转发，自定义助手的凭据从 `assistantbean` 读取。直连仅作为 `VITE_AI_GATEWAY=0` 的兼容开关保留。

问：如果 Dify 不可用，平台还能用吗？

答：能。登录、用户管理、能力广场、模型仓库、数据集等业务模块都不依赖 Dify，只有智能对话、知识库检索和文档预览不可用。

问：模型能换吗？

答：能。在 Dify 后台的模型供应商里配置新的模型（如 DeepSeek、通义），业务代码一行都不用改。这正是选择 Dify 作为 AI 底座的原因：把模型选型的变化隔离在平台层之外。
