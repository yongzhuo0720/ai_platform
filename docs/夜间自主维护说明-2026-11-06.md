### 2.2 一个必须写进 README 的环境坑

受限执行环境（沙箱的文件写入/批量删除防护）会让 `scripts/verify.ps1` 报红，但**不是代码回归**。我逐条复现并已把规避方式写进 `README.md`：

1. Vitest 内部 `Proxy.fetch` 写临时文件被 `node-brokered-fs-shim` 拦截（`EPERM`），表现为 `exit=1` + **静默少跑 1 个测试文件**。本轮组件测试因此漏跑 `AgentView.component.spec.ts`，单独补跑 22 项全过；早先逻辑单测也漏跑过 `useChatConversations.spec.ts`（16 项）。
2. Vite 清空 `dist/assets` 触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（110 个文件 > 50 阈值）——把旧 `dist` **移动**到临时目录（不删除）再 `npm run build` 即 exit=0。
3. Playwright 清理 `test-results` 触发同类告警——先移走旧 `test-results`。
4. 组件测试单独跑不受影响。

**教训**：看到门禁报红先读实际调用参数/日志，别急着改生产代码。我本轮就差点把「文档 286 项」误判成失真——实际是 270 + 16 分两次跑，文档没错。
