# 改进检查与学习计划

日期：2026-10-27。范围：当前工作区的 AI 网关、流式调用、RAG、模型配置与会话同步。检查前工作区已有改动，本次保留它们，在其基础上修复下面的问题；已有的流式超时、账户隔离和停止后保存部分回答等改动不计为本次新实现。

## 本次修复

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| Dify 查询身份可伪造 | `/conversations`、`/messages` 的 `user` 原样来自浏览器，同一应用密钥下存在跨用户查询风险 | 对话模块删除重复或 URL 编码的 `user` 参数，按后端认证 uid 写入唯一值，其他参数原样保留 |
| 上传身份缺失或可伪造 | multipart 原样转发，前端只提交文件时没有 Dify 所需的用户身份 | 保留文件内容，剔除客户端 `user` 部分，补入唯一的可信 uid |
| JSON 身份注入失败后放行 | 超过 2MB 时绕过注入且丢弃跨界数据块；畸形 JSON 也透传；未知长度的请求可能被忽略 | 超限返回 413；畸形、非对象或多段 JSON 返回 400；未知长度照常读取并校验，不向上游发送未校验的请求体 |
| 精排结果被网关重新打乱 | Rerank 已调整相关度顺序，网关又按旧 RRF 分排序，导致注入顺序退回召回结果 | 注入上下文直接沿用检索层最终顺序 |
| 向量与文本错配 | embeddings 的结果数组顺序变化时，原代码按数组位置配对，没有读取 `index` | 按 `index` 放回输入顺序；拒绝缺失、重复、越界索引，以及空向量、非数值或维度不一致的结果 |
| 禁用配置仍可调用 | 直连路由与精排配置解析没有检查 `enable=false` | 解析时跳过禁用配置；兼容历史记录未设置启用标记的情况 |
| 精排返回重复或越界索引 | 原代码只比较返回数量，`[0,0]` 也会通过，导致引用重复、候选丢失 | 校验索引完整、唯一且范围合法，异常时降级为原召回顺序 |
| 旧会话覆盖新快照、保存失败报成功 | 慢请求晚到时会覆盖较新消息；数据库更新或插入返回 0 仍返回成功 | 校验更新时间，拒绝旧快照，已有版本时间参与更新条件，检查实际写入结果 |

关键实现：`AiGatewayService`、`EmbeddingClient`、`ModelGatewayResolver`、`RerankResolver`、`ChatConversationHolder`。

补充工程改进：把现有的 `check-streaming.mjs` 接入 npm 命令、GitHub Actions 和本地验证脚本；修正 README 中“文档与向量全部在 Dify”和“Token 配额仅覆盖 Dify”等过时描述。

兼容性：Dify 对话身份现在统一为登录 uid。此前使用其他 `user` 标识创建的上游历史不会自动迁移；本次没有修改真实上游历史数据。会话保存要求携带正数的 `clientUpdatedAt`，当前前端已提供该字段。向量接口必须提供 OpenAI 兼容协议的 `index` 字段。

## 还应继续改什么

### 优先处理数据正确性

1. **文档入库的事务与唯一标识。** 当前先写 `ready` 文档，再逐条写分块，部分分块失败仍会返回成功；新文档 iid 通过“同名、同库、同用户取最新”查找，并发上传同名文档可能串联。下一步应直接获取插入主键，在向量化完成后用事务保存文档和全部分块，全部成功才标为 ready；用注入失败与并发上传测试验收。
2. **云端会话的服务端版本号。** 本次挡住了可比较的旧快照，并对已有时间版本做条件更新；仍需用数据库唯一约束保证 `(userId, convId)` 唯一，实现原子 upsert 和服务端递增版本。当前首次插入仍有竞争，历史空时间戳没有完整版本保护，客户端时钟偏差和相同毫秒冲突也未解决。删除最好使用版本或删除标记，防止旧设备重新同步已删除会话。
3. **引用与实际上下文保持一致。** 当前浏览器和网关分别检索一次：增加开销，而且默认 topK 也不同，界面展示的引用不一定等于模型收到的片段。应由网关返回本次真正使用的来源，让回答和引用共享同一次检索结果。

### 再提升可用性与性能

4. **RAG 可测量。** 为分块保存向量模型标识、版本与维度，切换模型时重建索引；先用黄金集取得真实基线，再比较纯向量、混合检索与精排。PostgreSQL `simple` 全文检索对中文词组召回有限，内存中的二元词项不能补回全文索引已经漏掉的候选，需专门评估中文分词方案。
5. **规模与缓存。** 目前向量路把个人分块全部读入 Java 算余弦。数据量增长后，基于实测延迟引入 pgvector 与向量索引。Rerank 配置有最长 5 分钟的进程缓存，后台改配置后应主动失效，尤其是禁用和更换密钥时。
6. **流式与治理。** 增加浏览器停止 → 网关断开 → 上游停止的联调测试；按并发请求预留 Token，减少请求完成后才扣额度造成的超额。当前记录的首块耗时是首段 SSE 字节到达时间，可能是心跳或元数据，不等于首个回答 token。

### 对前端求职最有价值的工程改进

7. **拆解 ChatView。** 约 2700 行逻辑逐步按职责分成 `useChatStream`、`useConversationSync`、`useChatAttachments`；先保留行为与页面，避免一次重写。重点理解请求取消、消息更新、生命周期清理与账号切换。
8. **补用户操作测试。** 优先覆盖发送 → 流式追加 → 停止保留部分内容 → 切换会话 → 刷新恢复，以及上传图片、重新生成、云端同步失败。Markdown 检查需要 jsdom 等 DOM 环境，并显式声明脚本依赖，再纳入 CI。
9. **按实际访问优化产物。** 构建中 Element Plus 分块约 1.05MB、gzip 约 331KB；应先测页面首屏和路由加载，再检查全量引入、按需加载与懒加载。PDF worker 应按使用场景加载，不要只靠调高警告阈值。

建议执行顺序：先把 1～3 的行为讲清楚并补验收，再围绕 7、8 做一个自己能独立演示的前端改进。为面试积累真实问题、定位证据和验证结果，比继续堆功能更有用。

## 接下来怎么带你学

一次只学一个小模块：先演示具体场景，再看少量关键代码，最后回答 3 个问题。回答不熟的地方补例子，不急着跳下一章。

| 顺序 | 模块 | 学完要能说明什么 |
|---|---|---|
| 1 | 请求身份与网关 | token、登录 uid、浏览器提交的 user 分别是什么；后端为什么必须覆盖身份 |
| 2 | 发送一条消息 | 输入框如何通知父组件；用户消息和 AI 占位消息何时创建 |
| 3 | SSE 流式与停止 | 一段数据如何更新同一条消息；取消请求、结束事件和超时的区别 |
| 4 | 会话保存 | 本地与云端分别存什么；旧请求为什么会覆盖新内容 |
| 5 | RAG 与引用 | 文档分块、向量、召回、精排和提示词注入分别解决什么 |
| 6 | 面试表达 | 用一条完整请求链和一个亲自复现的 bug 讲清项目 |

日常可用 4～5 小时分配：项目学习与操作 2 小时、相关 JS / Vue 基础 1 小时、独立小练习 1 小时、复盘与面试口述 30 分钟。第一轮重点是自己理解并验证已有模块，再逐步减少 AI 代写比例。

面试描述以实际参与为准：可以讲“接手维护与迭代，借助 AI 定位问题，自己复现、验证并理解修复”，不要把尚未理解的整套架构说成独立设计。
