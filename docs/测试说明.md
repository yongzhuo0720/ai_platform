# 测试说明：可重复执行的命令清单

最后更新：2026-10-30
适用于：本地 Windows + Git Bash / PowerShell 环境

这份文档的目的是让**任何人（包括三个月后的你自己）**都能用一条命令把项目的质量门禁跑一遍，
不需要回忆当时是怎么配的环境。

---

## 0. 先确认环境（最容易踩的坑）

| 检查项 | 要求 | 怎么确认 |
|---|---|---|
| JDK | **必须是 8**，不能是 21 | `java -version` 应显示 `1.8.x` |
| Maven | 3.6+ | `mvn -v` |
| Node | 22+（jsdom 30 官方要求 ≥22.22；本机 22.20 实测可跑，CI 用最新 22） | `node -v` |
| 前端依赖 | 已安装 | `frontend/node_modules` 存在 |

### ⚠️ 坑一：默认 JAVA_HOME 是 JDK 21，但项目要 JDK 8

本机默认 `JAVA_HOME` 指向 JDK 21，而项目目标是 Java 8。
用 JDK 21 跑会失败，且**报错信息具有误导性**（Lombok 相关的奇怪错误）。

```bash
export JAVA_HOME="/d/DevTools/Java_jdk 1.8"
export PATH="$JAVA_HOME/bin:$PATH"
java -version   # 确认输出 1.8.x
```

### ⚠️ 坑二：直接 `mvn test` 会失败，必须指定离线 settings

默认的 `~/.m2/settings.xml` 里配置了 `<mirrorOf>*</mirrorOf>`，
它会把**所有**仓库请求（包括私有框架仓库）转到阿里云，
于是 `com.heneng.hnsp` 系列依赖解析不到：

```
Could not find artifact com.heneng.hnsp:hnsp-public-common-croe:jar:1.2.3-SNAPSHOT
```

项目自带了一份正确的 settings（`hd_redis/ai-maven/conf/settings.xml`），
它的 `<mirrorOf>central</mirrorOf>` 不会拦截私有仓库。**必须显式指定它。**

### ⚠️ 坑三：`mybatis` 版本被框架声明成 `LATEST`

私有框架 `hnsp-public-common-croe` 在自己的 pom 里写的是
`<version>LATEST</version>`，Maven 会去拉当前最新版。

2026-10-29 实测：当天 16:55 构建正常，16:57 元数据刷新后拉到
`mybatis 3.6.0`（Java 11 编译，class 版本 55.0），JDK 8 直接编译失败：

```
class file has wrong version 55.0, should be 52.0
```

已在根 `pom.xml` 用 `dependencyManagement` 锁定 `3.5.19`。
**这个锁定不要移除**，否则构建会在任意时刻自己坏掉。

## 2. 前端检查与构建

```bash
cd /d/ai_project/ai_platform/frontend

npm run typecheck        # TypeScript 类型检查（strict 模式）
npm run check:icons      # 图标注册检查：模板图标必须 import 或全局注册
npm run test             # 单元测试（Vitest）：8 个文件 / 142 个用例
npm run check:streaming  # SSE 流式回归：14 项
npm run check:markdown   # Markdown 渲染与 XSS 消毒回归：10 项
npm run build            # 生产构建
```

**预期结果**：全部通过。构建仍有 `element-plus` 分包 922.89 kB / gzip 296.83 kB 的
体积警告（2026-10-30 图标按需注册后从 1,052.14 kB / 331.25 kB 降下来），
属已知项，不影响功能。

### 关于图标注册（2026-10-30 新增）

`main.ts` 此前用 `import * as ElementPlusIconsVue` 把 **293 个图标全部全局注册**，
不论页面用没用到都会进首屏。实际模板与导航数据只用到 56 个，改为：

- 组件内直接 `import { Xxx } from '@element-plus/icons-vue'`（默认做法）；
- 只有 `data/*.ts` 的字符串图标和组合式函数返回给模板的图标，才登记到 `main.ts`
  的 `globalIcons`（当前 23 个）。

这样 Element Plus 分块从 1,052.14 kB 降到 922.89 kB（gzip 331.25 → 296.83 kB）。

代价是"模板用了图标但忘了 import"不会再报错，只会**静默留白**。所以新增
`npm run check:icons`：逐文件核对模板里的图标标签与 `icon: 'Xxx'` 字符串，
既没 import 也没全局注册就失败；同时禁止 `import *` 回归。
已用临时探针文件验证过它能拦住漏注册的情况。

### 关于 `check:markdown` 的一段历史

这个脚本在 2026-10-29 之前**一直是失败的**，报错：

```
TypeError: purify_default.sanitize is not a function
```

原因是 `markdown.ts` 用 DOMPurify 做 XSS 消毒，而 DOMPurify 在**模块导入时**
就要读 `window`；Node 里没有 `window`，于是拿到未初始化的实例。

**这意味着那 10 条 XSS 断言从来没真正执行过** ——
"防住了 `javascript:` 链接"、"防住了 `<img onerror=...>`" 这些结论此前是没有验证的。

修复方式：在导入 `markdown.ts` 之前用 `jsdom` 注入 DOM 环境（见
`scripts/check-markdown.mjs` 顶部）。`jsdom` 是**仅测试用**的 devDependency，不进生产包。

### 关于 `npm run test`（2026-10-30 新增）

ChatView 拆分后，纯逻辑集中到了 `frontend/src/views/ChatView/` 下的
`chatFormat` / `chatStorage` / `useChatSelectors` / `chatComposerState` /
`chatAssistantState` / `useChatHistory` / `useChatSend`。这些模块不依赖 SFC 渲染，
用 Vitest + jsdom 直接跑，覆盖面包括：

| 模块 | 关键断言 |
|---|---|
| `chatFormat` | 文件类型图标、文件大小、Markdown 渲染、脚本与 `javascript:` 链接拦截 |
| `chatStorage` | 按 uid 隔离的存储键、JSON 损坏与写入失败时的降级 |
| `useChatSelectors` | 提交校验（必填变量/附件）、会话过滤与置顶排序、直连会话过滤、时间分组与摘要 |
| `chatComposerState` | 输入控件归一化、模型下拉过滤（重排/向量/停用模型不出现）、文件变量探测 |
| `chatAssistantState` | 编辑/删除权限（内置/本人/他人）、弹窗状态、删除后的列表重建 |
| `useChatHistory` | 历史消息映射（剥离思考块）、分页游标、**旧响应竞态丢弃** |
| `useChatSend` | 重新生成的前置条件、直连发送、附件兜底提问 |
| `directModel` | SSE 解析：`kb_sources` 来源事件、事件复位、错误事件、增量拼接 |

两点实现说明：

1. `vitest.config.ts` 独立于 `vite.config.ts`，只挂 `@` 别名与 jsdom，不加载 Vue 插件和样式处理。
2. 逻辑层会 `import { ElMessage } from "element-plus"`，真实包会拉起整套组件树；
   测试里通过 alias 指向 `src/test/element-plus-stub.ts`，不产生真实 UI。

**这套测试上线时就抓到一个真实缺陷**：xlsx 的 MIME
（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`）包含
`officedocument`，被 Word 分支抢先命中，Excel 文件一直显示成 Word 图标。
已调整 `getFileTypeEmoji` 的判定顺序并加用例锁定。

### 关于 RAG 引用一致性（2026-10-30 新增）

修复前：直连 + 知识库模式下，浏览器调用 `/api/kbRag/search` 拿引用，
网关转发时又检索一次做上下文注入。两次检索默认 topK 不同、结果可能不同，
**界面上展示的引用不一定等于模型真正读到的片段**，还多了一次检索开销。

现在网关在转发上游 SSE 之前，先写一帧来源事件：

```
event: kb_sources
data: {"items":[{"docIid":1,"docName":"手册.md",...}]}
```

前端 `directModel` 解析该事件，经 `onKbSources` 写回消息；`useChatDirect`
删掉了自己的检索请求。`X-KB-Hits` 保留，值等于实际注入的片段数。

顺带修正 SSE 解析：`event` 字段此前从不复位，自定义事件之后的上游增量块
会被误判；现在每个 data 事件处理完立即复位，并有单测锁定。

## 5. 测试覆盖了什么，没覆盖什么

### 已覆盖

| 领域 | 说明 |
|---|---|
| 权限与越权 | 知识库可见性 fail-closed、助手归属、角色查询收敛、部门/标签写接口鉴权 |
| AI 网关 | 身份覆盖、上传转发、畸形/超大请求拒绝、usage 解析、模型路由 |
| 本地 RAG | 向量对齐、指标算法、黄金集一致性 |
| 会话同步 | 旧快照拦截、带版本条件更新、保存失败不报成功 |
| SSE | 首字节超时、空闲超时、取消、跨 chunk 拼接 |
| Markdown/XSS | `javascript:` 拦截、`onerror` 拦截、URL 白名单、表格包裹 |
| 前端逻辑层 | ChatView 拆分模块：格式化、存储降级、会话过滤/分组、表单归一化、助手权限、分页竞态、发送与重新生成 |
| 图标注册 | 模板/数据里用到的图标必须 import 或全局注册，禁止 `import *` 全量注册回归 |
| RAG 引用一致性 | 来源事件先于上游 SSE、内容与注入片段同源、`kb_name` 不透传上游 |

### 未覆盖（诚实清单）

| 缺口 | 原因 |
|---|---|
| Controller 层 / API 集成测试 | 没有引入 MockMvc，也没有独立测试库 |
| 真实越权端到端验证 | 需要起服务 + 普通账号 + 独立测试库 |
| SSE 真实断流与压测 | 需要 mock 上游 + 并发场景 |
| 配额并发击穿 | 需要并发请求验证 |
| 前端组件渲染测试 | 已有逻辑层单测（Vitest），但未引入 `@vue/test-utils`；SFC 的渲染与点击交互仍靠人工冒烟 |
| 真实上游质量与容量 | 不连接真实 Dify / 生产数据库 |

**不要把这些未覆盖项说成"已验证"**，面试时尤其要注意。
