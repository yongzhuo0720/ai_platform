# 阶段 1 · 子阶段 7D：前端统一错误兜底

## 1. 业务目标

此前前端有三套互不相干的错误处理：

| 链路 | 行为 |
| --- | --- |
| axios 响应拦截器 | 非 0 `resp_code` 弹 `ElMessage`；网络错误按状态码给文案 |
| `installPreloadRecovery` | 懒加载 chunk 404 时自动重载一次 |
| 其余异常 | 只进浏览器控制台 |

这留下两个真实缺口：

1. **渲染 / 生命周期异常对用户完全不可见**——页面局部白屏，用户不知道发生了什么，
   刷新后又可能恢复，问题无法被反馈；
2. **未处理的 Promise rejection 没有任何兜底**——控制台一条红字，用户侧毫无感知。

本子阶段加一层最小兜底：

> Vue 渲染/生命周期异常与未处理的 Promise rejection，统一显示一条顶部横幅；
> 横幅带**错误编号**、支持关闭与重新加载；同一错误短时间内重复出现只累计次数；
> 已经由其他机制处理的错误（chunk 404、axios、主动取消）不再重复提示。

不做的事：

- 不引入 Sentry 等外部上报（公开仓库不接第三方、也不希望把堆栈发出去）；
- 不改 axios 的既有行为（业务错误继续用 toast，保持原有交互）；
- 不接管 `window.onerror`：Vue 组件内错误已由 `app.config.errorHandler` 捕获，
  剩余多为跨域脚本噪声，收益低、误报多。

## 2. 错误分流

```text
                       ┌──────────────────────────────┐
Vue 渲染/生命周期 ────▶ │ app.config.errorHandler      │──┐
未处理 rejection ─────▶ │ window unhandledrejection    │──┤
                       └──────────────────────────────┘  │
                                                         ▼
                                                isIgnored(error)?
                                        ┌───────────────┴───────────────┐
                                        │ 是                            │ 否
                                        ▼                               ▼
      chunk 加载失败 → preloadRecovery 重载                  globalErrorCenter.report
      axios 错误     → 拦截器已 toast                         │
      Abort/Cancel   → 正常取消                               ▼
      ResizeObserver → 浏览器噪声                      8 秒内同错？累计次数
                                                        │否
                                                        ▼
                                              生成错误编号 + 显示横幅
                                                        │
                                        ┌───────────────┴───────────────┐
                                        ▼                               ▼
                                    点击关闭                        点击重新加载
                                  （仅隐藏横幅）                  location.reload()
```

## 3. 设计取舍

| 决策 | 原因 |
| --- | --- |
| 用常驻横幅，不用 toast | toast 几秒后消失，用户来不及记错误编号；渲染异常往往需要「看完再决定刷新」 |
| 状态放在模块级 `reactive`，不放 Pinia | 错误中心必须在 Pinia 之外也能工作（比如 store 初始化失败）；组件只读它 |
| 每个错误都生成编号 | 用户反馈「页面出问题」无法定位；编号 + 控制台堆栈能把两端对上 |
| 同错 8 秒内去重 | 一个渲染循环可能每帧抛错，不去重会刷屏；去重后仍累计次数，能看到严重程度 |
| 去重时复用编号 | 同一问题应始终对应同一编号，方便客服/开发沟通 |
| 保留 `previous` errorHandler | 测试或未来插件可能先注册处理器，直接覆盖会丢行为 |
| `unhandledrejection` 不 `preventDefault` | 浏览器控制台仍应保留原始报错，方便开发排查 |
| 卸载函数 | 测试需要干净的监听器状态；也避免热更新重复注册 |

## 4. 后端/前端职责边界

本子阶段只在前端，没有后端改动：

- 服务端错误仍由 axios 拦截器呈现（toast / 跳登录）；
- 前端异常编号只用于定位**客户端**问题，不回传服务端，不新增接口；
- 如果将来要接错误上报，`report()` 是唯一出口，接入点已经收敛。

## 5. 核心代码

### 5.1 错误中心

```ts
export function createErrorCenter(options: CenterOptions = {}): GlobalErrorCenter {
  const state = reactive<GlobalErrorState>({
    visible: false, errorId: '', message: '', count: 0, at: 0,
  })
  let lastKey = ''
  let lastAt = 0

  function report(error, source = 'promise', info?) {
    if (isIgnored(error)) return
    const raw = messageOf(error)
    const message = raw.length > 160 ? `${raw.slice(0, 160)}…` : raw
    const at = now()
    logger.error(`[GlobalError] source=${source}${info ? ` info=${info}` : ''}`, error)

    if (lastKey === message && at - lastAt < dedupeWindowMs) {
      state.visible = true
      state.count += 1
      state.at = at
      return
    }
    lastKey = message
    lastAt = at
    state.visible = true
    state.errorId = nextErrorId(at, random)
    state.message = message || '未知错误'
    state.count = 1
    state.at = at
  }

  function dismiss() { state.visible = false }

  return { state, report, dismiss }
}

export const globalErrorCenter = createErrorCenter()
```

`now` / `random` / `logger` 都可注入，测试里能精确控制去重窗口与编号。

### 5.2 安装与卸载

```ts
export function installGlobalErrorHandling(app, options = {}): () => void {
  const center = options.center ?? globalErrorCenter
  const target = options.target ?? window
  const previous = app.config.errorHandler

  const handler = (error, instance, info) => {
    previous?.(error, instance, info)
    center.report(error, 'vue', info)
  }
  app.config.errorHandler = handler

  const onRejection = (event: Event) => {
    center.report((event as PromiseRejectionEvent).reason, 'promise')
  }
  target.addEventListener('unhandledrejection', onRejection)

  return () => {
    if (app.config.errorHandler === handler) app.config.errorHandler = previous ?? undefined
    target.removeEventListener?.('unhandledrejection', onRejection)
  }
}
```

`main.ts` 在 `createApp` 之后、`mount` 之前调用，保证首屏渲染异常也能被接住。

### 5.3 忽略规则

```ts
function isIgnored(error: unknown): boolean {
  if (isChunkLoadError(error)) return true
  if ((error as { isAxiosError?: boolean })?.isAxiosError) return true
  if (name === 'AbortError' || name === 'CanceledError') return true
  return /ResizeObserver loop (limit exceeded|completed with undelivered notifications)/.test(message)
}
```

`isChunkLoadError` 放在 `preloadRecovery.ts` 并导出，让「什么算 chunk 错误」只有一处定义：
Vite 的 `Failed to fetch dynamically imported module`、浏览器的
`Importing a module script failed`、旧打包器的 `ChunkLoadError` 都覆盖。

### 5.4 横幅组件

`GlobalErrorBanner` 通过 `Teleport to="body"` 固定在最上层：

- `role="alert"` + `aria-live="assertive"` + `aria-atomic="true"`；
- 标题 + 出现次数 + 原始错误信息（截断 160 字）+ 错误编号；
- 「重新加载」（主按钮）与「关闭」（次按钮）；
- 颜色全部用设计变量（`--danger` / `--danger-soft-strong` / `--surface-card-strong`），
  不新增硬编码色值；移动端按钮换行到第二行。

## 6. 异常处理

| 场景 | 行为 |
| --- | --- |
| 渲染函数抛错 | Vue 捕获 → 横幅；组件树由 Vue 继续处理（通常是局部卸载） |
| `setup` / 生命周期抛错 | 同上 |
| 未处理的 `Promise.reject` | 横幅 |
| `Promise.reject('字符串')` | 横幅显示字符串 |
| `Promise.reject(null)` / 非 Error 对象 | 横幅显示「未知错误」 |
| chunk 404 | 不显示横幅，由 preloadRecovery 自动重载 |
| axios 业务错误 | 不显示横幅，拦截器已 toast / 已跳登录 |
| 主动取消请求 | 不显示横幅 |
| 同一错误连续出现 | 8 秒内累计次数，编号不变 |
| 用户点关闭 | 仅隐藏；再次出现会重新展示 |
| 用户点重新加载 | 整页刷新，重新拉取资源清单 |

## 8. 已知边界

1. **不做持久化**：刷新后错误记录消失；需要长期留存应接日志平台。
2. **只展示最后一条**：多个不同错误先后出现时会覆盖上一条，不排队。
3. **main.ts 模块求值阶段异常**：入口脚本自身在安装处理器之前抛错，无法显示横幅；
   这类问题仍看控制台。
4. **不采集用户操作路径**：没有面包屑（breadcrumb），复杂问题仍需复现步骤。
5. **组件自身异常**：如果横幅组件渲染失败，可能反复报告；当前组件足够简单，未加自保护。

## 9. 面试题

### Q1：为什么不用 `window.onerror`？

Vue 组件内的渲染/生命周期错误会被 Vue 自己捕获并交给 `app.config.errorHandler`，
不会再冒泡到 `window.onerror`；真正落到 `window.onerror` 的多是跨域脚本的
`Script error.` 或第三方脚本噪声。接它收益低、误报多，所以只接 Vue 处理器 +
`unhandledrejection`，范围更可控。

### Q2：为什么 axios 错误不显示横幅？

axios 拦截器已经按业务语义提示过：业务错误 toast、401/403 跳登录、silent 请求刻意静默。
再弹横幅会重复打扰，而且把「接口报错」和「页面坏了」混在一起，用户无法区分严重程度。

### Q3：为什么要错误编号？

用户只能描述「页面出问题了」，开发和客服无法对上具体异常。编号同时在横幅和控制台日志里，
用户报编号即可定位到那次堆栈。编号由时间戳 + 随机后缀组成，不需要服务端配合。

### Q4：去重为什么用「消息」而不是堆栈？

堆栈里包含行号与调用链，同一类错误每次可能略有差异，去重效果差；
消息更稳定，且足以代表「同一个问题」。代价是不同位置抛出的同文案错误会合并，
对用户侧展示来说可以接受。

### Q5：为什么状态不放进 Pinia？

错误中心要覆盖「Pinia 初始化失败」「store 定义抛错」这类场景，
依赖 Pinia 会形成循环。模块级 `reactive` 没有初始化依赖，放哪都能用。

### Q6：chunk 错误为什么要专门过滤？

`preloadRecovery` 已经会 `preventDefault` 并重载页面。如果全局处理器再弹横幅，
用户会先看到「页面出问题了」，紧接着页面刷新——两个反馈互相矛盾。
让 chunk 错误只有一条处理路径。

### Q7：为什么保留 `previous` errorHandler？

覆盖式赋值会悄悄丢弃之前注册的行为（测试工具、监控插件都可能先注册）。
追加调用既保证自己的逻辑执行，也不破坏别人的钩子；卸载时再恢复原值。

### Q8：`unhandledrejection` 要不要 `preventDefault`？

不要。阻止默认行为会让控制台不再打印「Uncaught (in promise)」，等于把开发排查的线索抹掉。
我们的横幅只是补充用户侧反馈，不应改变浏览器原有行为。

### Q9：怎么测试这种「全局钩子」？

把不确定的依赖都做成参数：`target`（事件源）、`center`（状态容器）、
`now`/`random`/`logger`（时间、编号、日志）。测试传假对象即可精确断言，
不需要真的制造未处理 rejection，也不依赖时序。

### Q10：错误横幅和「降级/空态」是什么关系？

不是一层东西：
空态/降级是**预期内**的业务状态（没有数据、某个数据源失败），由页面自己渲染；
全局横幅是**预期外**的客户端异常（代码抛错），页面自己已经不可信了。
两者都叫「错误提示」，但处理层级与责任方不同。
