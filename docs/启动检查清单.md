# 启动检查清单

> 用途：面试前一天照着走一遍，确保现场能演示。**全程约 15 分钟**。
> 不配 Dify 也能跑通 80% 的页面；配了 Dify 才能演示对话和知识库问答。
> AI 调用默认经后端网关：Dify 配置填在**后台「Dify 配置管理」**（或服务端 `DIFY_*` 环境变量），
> 前端 `.env.local` 不再生效。

---

## 0. 前置检查（2 分钟）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| JDK | **必须是 8**（Java 21 与本项目的 Lombok 版本不兼容） | `java -version` 看到 `1.8` |
| Node | 18+ | `node -v` |
| PostgreSQL | 已启动，监听 **5432**，库 `ai` 存在 | `netstat -ano \| findstr 5432` |
| Redis | 已启动，监听 **6379**，密码 `zxcvbnm` | `netstat -ano \| findstr 6379` |

### 这两个组件的启动方式（2026-10-15 已配置好）

**Redis** —— 已注册为 **Windows 服务 `RedisAI`**，开机自启，**无需手动启动**：

```powershell
Start-Service RedisAI     # 手动启停用这个，任意目录可执行
netstat -ano | findstr 6379
```

> 配置文件：`hd_redis\redis321\redis.windows.conf`。
> 注意两处历史坑：① conf 里写 Windows 路径必须用**正斜杠**（`\a` `\r` 是转义符）；
> ② `--service-install` 传的 conf 参数**必须绝对路径**（服务运行时工作目录是 System32）。

**PostgreSQL** —— 绿色版位于 `hd_redis\pgsql`，**未装服务**，每次要手动启动，且**必须用非管理员 PowerShell**（PG 拒绝以管理员权限运行）：

```powershell
cd "D:\ai_project\ai_platform\hd_redis\pgsql"
.\bin\pg_ctl.exe -D "D:\ai_project\ai_platform\hd_redis\pgsql\data" -l "pgsql-start.log" start
```

> 自启用任务计划程序：登录时运行 `bin\pg_ctl.exe`，参数 `start -D "<data 绝对路径>"`。
> 不要用 `pg_ctl register` 装服务——默认以 LocalSystem 运行，PG 会拒绝。

### 建议：本地先把 SSO 关掉

`application-dev.properties` 里 `sso.enabled=true`，而 issuer 默认指向示例地址，
本地连不上，启动时会刷一堆连接失败的日志——**不影响账号密码登录**，但看着闹心。

演示前建议临时改成：

```properties
sso.enabled=false
```

## 1. 启动后端（约 3 分钟）

私有 Maven 依赖就在仓库内的 `hd_redis/ai-maven`，可离线构建：

```powershell
$repo     = (Resolve-Path hd_redis/ai-maven/pro).Path
$settings = (Resolve-Path hd_redis/ai-maven/conf/settings.xml).Path
$env:JAVA_HOME = 'D:/DevTools/Java_jdk 1.8'   # 改成你自己的 JDK 8 路径

Set-Location backend/AIProject
mvn -s $settings "-Dmaven.repo.local=$repo" -o package
```

然后在 IDE 里运行 `app-start` 模块的启动类，或继续用 Maven 启动。

**启动成功的标志**：

- 监听 **8507**，上下文路径 **`/ai`**
- 日志里出现表结构初始化、Dify 配置注册相关信息
- 浏览器打开 <http://127.0.0.1:8507/ai/api/difyConfigBean/query> 不再是连接拒绝

启动时会自动执行**表结构初始化**和**基础配置注册**，都是幂等的，重复启动没问题。

## 2. 启动前端（约 2 分钟）

```bash
cd frontend
npm install     # 首次或依赖有变化时
npm run dev
```

默认开在 <http://localhost:5173>。dev proxy 已把 `/ai` 转到 8507，所以前端能直接调后端。

> 想确认改动没写坏，可以再跑一次 `npm run typecheck`（当前基线 26 条历史错误，只要没新增就行）。

## 4. 出问题怎么排查

| 现象 | 原因 / 处理 |
|---|---|
| 后端起不来，报数据库连接失败 | PostgreSQL 没启动，或 `postgres/zxcvbnm` 账密对不上 |
| 后端报 Redis 连接失败 | Redis 未启动，或端口与 `hnsp.redis.port` 不一致 |
| 编译报 Lombok 相关错误 | JDK 版本不对，必须是 **Java 8** |
| Maven 拉不到依赖 | 少了 `-s` 和 `-Dmaven.repo.local` 两个参数，或没加 `-o` |
| 前端页面白屏 | 打开控制台看报错；多半是接口 500 或路由问题 |
| 前端接口 404 | 后端没起来，或 dev proxy 没生效（确认后端在 8507） |
| 登录一直失败 | 确认用的是账号密码登录；SSO 需要外部 OpenID 服务，本地不可用 |
| 启动日志刷 SSO 连接失败 | 正常，不影响使用；可把 `sso.enabled` 设为 false |
| 对话/知识库返回 503 `gateway_not_configured` | 后台「Dify 配置管理」填地址与密钥，或给后端配 `DIFY_CHAT_URL` / `DIFY_CHAT_KEY` 等环境变量 |
| 对话返回 429 `rate_limited` / `quota_exceeded` | 触发每分钟限流或每日 Token 配额；等待下一分钟/次日，或在「AI 调用治理 → 配额管理」调整 |
| 改了 `.env.local` 但对话仍走旧配置 | 默认网关模式忽略 `VITE_DIFY_*`；要么填后台配置，要么设 `VITE_AI_GATEWAY=0` 切回直连 |

## 附：想让 AI 功能也能演示

需要自己的 Dify（云端 dify.ai 有免费额度，或用 docker 自建）。拿到之后二选一：

**方式 A（推荐）：后台页面配置**

1. 用管理员登录 `/admin`
2. 打开「Dify 配置管理」，给「问答聊天对话」填 API 地址（如 `https://api.dify.ai/v1`）与应用密钥（`app-` 开头）
3. 知识库相关模块再填 `dataset-` 开头的知识库密钥
4. 保存后直接在前端对话，**不需要重启后端**

**方式 B：服务端环境变量**

启动后端前设置（数据库为空时生效）：

```bash
DIFY_CHAT_URL=https://api.dify.ai/v1
DIFY_CHAT_KEY=app-你的应用密钥
DIFY_KB_FILE_URL=https://api.dify.ai/v1
DIFY_KB_FILE_KEY=dataset-你的知识库密钥
```

> 默认网关模式下 `frontend/.env.local` 的 `VITE_DIFY_*` 不参与转发；只有设置 `VITE_AI_GATEWAY=0` 才恢复浏览器直连（密钥会下发浏览器，且无限流/配额/审计）。
> 另外换 Dify 后，本地库里已登记的知识库 `kbId` 仍指向旧的 dataset，需要在新 Dify 里重建并重新登记。
